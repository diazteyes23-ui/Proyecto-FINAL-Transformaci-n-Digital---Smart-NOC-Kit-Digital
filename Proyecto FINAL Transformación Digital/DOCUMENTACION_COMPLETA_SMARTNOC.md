## FASE 1 — ANÁLISIS DEL KIT DIGITAL {#fase-1}

### 1.1 ¿Qué es el Kit Digital?

El **Kit Digital** es una iniciativa del Gobierno de España, enmarcada dentro del **Plan de Recuperación, Transformación y Resiliencia**, financiado con fondos europeos **Next Generation EU**. Es gestionado por la entidad pública **Red.es**, adscrita al Ministerio de Asuntos Económicos y Transformación Digital, a través del portal **Acelera Pyme** (acelerapyme.gob.es).

Su objetivo principal es **impulsar la digitalización de pequeñas y medianas empresas (pymes) y autónomos españoles**, proporcionando subvenciones directas (denominadas "bonos digitales") para que contraten soluciones digitales con Agentes Digitalizadores homologados.

### 1.2 Objetivo del Programa

| Aspecto | Detalle |
|---|---|
| **Financiación** | Fondos europeos Next Generation EU |
| **Marco legal** | Reglamento (UE) 2021/241 — Mecanismo de Recuperación |
| **Convocatoria** | C005/23-SI — Bases reguladoras publicadas en BOE |
| **Fin** | Digitalizar pymes con soluciones tecnológicas reales |
| **Importe máximo** | Hasta 12.000 € (segmento I: 10-49 empleados) |

### 1.3 Beneficiarios del Programa

El programa distingue tres segmentos de empresas:

- **Segmento I:** Empresas de 10 a 49 empleados → Bono de hasta **12.000 €**
- **Segmento II:** Empresas de 3 a 9 empleados → Bono de hasta **6.000 €**
- **Segmento III:** Empresas de 0 a 2 empleados (microempresas y autónomos) → Bono de hasta **2.000 €**

**Requisitos para ser beneficiario:**
- Ser pyme o autónomo con domicilio fiscal en España
- Estar inscrito en el Censo de Empresarios de la AEAT
- No tener la consideración de empresa en crisis
- Estar al corriente de obligaciones tributarias y con la Seguridad Social
- No superar los límites de minimis de ayudas de Estado

### 1.4 Categorías de Soluciones del Kit Digital

| Categoría | Descripción |
|---|---|
| Sitio Web y Presencia Online | Creación o mejora de página web corporativa |
| eCommerce | Tienda online con carrito y pasarela de pago |
| Gestión de Redes Sociales | Planificación y publicación de contenidos |
| **CRM** | **Gestión de relaciones con clientes** |
| **BI y Analítica** | **Dashboards, KPIs, análisis de datos** |
| **Gestión de Procesos** | **ERP, gestión operativa y flujos de trabajo** |
| Factura Electrónica | Facturación compatible con TicketBAI / Verifactu |
| **Ciberseguridad** | **Protección frente a amenazas digitales** |
| Comunicaciones Seguras | Correo corporativo cifrado, VPN |
| Puesto de Trabajo Seguro | Dispositivos y software con gestión centralizada |

> **Categorías aplicadas en este proyecto (negrita):** Gestión de Procesos, BI y Analítica, Ciberseguridad — todas cubiertas por la solución Smart NOC.

### 1.5 El Agente Digitalizador

Un **Agente Digitalizador** es una empresa TIC homologada por Red.es que:

1. **Se adhiere** al programa mediante la Sede Electrónica de Red.es (sede.red.gob.es)
2. **Publica** sus soluciones en el catálogo oficial de Acelera Pyme
3. **Firma** un Acuerdo de Prestación de Soluciones Digitales con el beneficiario
4. **Implanta** la solución en el plazo máximo de 12 meses
5. **Justifica documentalmente** la ejecución ante Red.es para cobrar el bono
6. **Forma** al usuario final en el uso de la solución

**Funciones clave del Agente Digitalizador:**
- Diagnóstico digital de la empresa cliente (auditoría)
- Diseño e implantación de la solución tecnológica
- Formación y soporte post-implantación (mínimo 12 meses)
- Documentación de la justificación para la administración

### 3.2 Nivel de Digitalización Actual

**Índice de Madurez Digital (DMA): 2 / 5 — Básico-Emergente**

| Proceso | Herramienta actual | Nivel |
|---|---|---|
| Gestión de incidencias | Hojas de cálculo Excel | 🔴 Muy bajo |
| Comunicación con técnicos | WhatsApp y llamadas telefónicas | 🔴 Muy bajo |
| Ticketing / ITSM | Sin sistema integrado | 🔴 Sin digitalizar |
| Monitorización de red | Herramientas legacy desconectadas | 🟡 Básico |
| Análisis de datos | Sin explotación de datos | 🔴 Sin digitalizar |
| Gestión documental | Papel y correo electrónico | 🟡 Básico |
| Ciberseguridad | Sin política formal | 🔴 Muy bajo |

### 3.3 Diagnóstico — Carencias Digitales

#### Carencias Críticas Identificadas

1. **❌ Sin sistema de gestión de incidencias (ITSM):** Las incidencias se registran manualmente en Excel sin trazabilidad ni histórico estructurado.

2. **❌ Sin digitalización del proceso NOC → Campo:** El flujo de despacho de técnicos es completamente manual (llamada telefónica), sin optimización de rutas ni asignación inteligente.

3. **❌ Sin análisis predictivo de fallos:** Los ~500 GB/mes de telemetría de red generados no se explotan, perdiendo la oportunidad de actuar de forma proactiva antes de que fallen los servicios.

4. **❌ Sin API documentada entre sistemas:** Los sistemas de red, operaciones y campo son silos sin integración, multiplicando el trabajo manual de los operadores.

5. **❌ Brechas de ciberseguridad graves:**
   - Credenciales compartidas entre técnicos para acceder a OLTs (sin rotación)
   - Tráfico de gestión de red sin separación VLAN
   - Logs con IPs de clientes sin seudonimizar (incumplimiento RGPD)
   - Endpoints de API legacy sin autenticación

6. **❌ Sin tratamiento estructurado de datos:** No existe data governance, ni retención definida, ni pipeline de datos para BI.

### 3.4 Oportunidades Detectadas

| Oportunidad | Impacto estimado |
|---|---|
| MTTR actual 4,2h → objetivo 1,7h | Reducción del 60% en tiempo de resolución |
| 30% de averías evitables con mantenimiento predictivo | Mejor experiencia de cliente |
| Automatización de despacho de técnicos | Ahorro 180.000 €/año en desplazamientos |
| Supresión de alarmas redundantes | Reducción de 85% en alarmas accionables |
| Reducción de personal nocturno L1 | Ahorro 480.000 €/año en OPEX |
| Elegible Kit Digital: Gestión de Procesos + BI | Subvención hasta **6.000 €** (seg. I) |

### 3.5 Cumplimiento del Kit Digital por Categoría

|---|---|---|---|
| **Gestión de Procesos (ERP)** | Excel manual | ❌ NO | Implantar Smart NOC (este proyecto) |

| **Ciberseguridad** | Accesos no auditados | ❌ NO | ENS + Zero Trust + auditoría |

### 3.6 Análisis de Brechas de Seguridad

| Área | Riesgo | Propuesta de mejora |
|---|---|---|
| Acceso a OLTs | Credenciales compartidas sin rotación | PAM (CyberArk / HashiCorp Vault) |

## FASE 4 — DISEÑO DE LA SOLUCIÓN DIGITAL {#fase-4}

### 4.1 Nombre y Categoría de la Solución

**Nombre:** Smart NOC — Sistema de Gestión Inteligente del Centro de Operaciones de Red  
**Categoría Kit Digital:** Gestión de Procesos + BI y Analítica + Ciberseguridad

### 4.2 Objetivos del Sistema

1. **Digitalizar** la gestión de incidencias de red eliminando el Excel manual
2. **Automatizar** el despacho de técnicos de campo mediante un sistema FSM
3. **Explotar** los datos de telemetría de red para análisis predictivo de fallos
4. **Integrar** NOC, campo y dirección en un único ecosistema digital vía API REST
5. **Cumplir** con ENS, RGPD y NIS2 en el tratamiento de datos de red

### 4.3 Funcionalidades del Sistema

| Módulo | Funcionalidades |
|---|---|
| **Gestión de Incidencias** | Alta, seguimiento, cierre, cálculo MTTR automático, código auto-generado |
| **Gestión de Técnicos** | Registro, disponibilidad, skills, geolocalización de zona |
| **Gestión de Equipos** | Inventario OLTs, BTS-5G, routers, estado operativo |
| **Órdenes de Trabajo (FSM)** | Despacho, asignación a técnico, SLA, seguimiento de estado |
| **Dashboard KPIs** | MTTR promedio, incidencias activas, técnicos disponibles |
| **API REST documentada** | Swagger UI, endpoints GET/POST/PUT para todos los módulos |
| **Frontend Web** | Propuesta de valor, auditoría, arquitectura, dashboard live |

### 5.2 Arquitectura MVC Implementada

#### MODEL — Entidades JPA

**Incidencia.java:**
```java
@Entity
@Table(name = "incidencias")
public class Incidencia {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String codigo;        // Auto-generado: INC-YYYYMMDD-XXX
    private String titulo;
    private Severidad severidad;  // Enum: P1, P2, P3, P4
    private EstadoIncidencia estado; // ABIERTA, EN_PROGRESO, RESUELTA, CERRADA
    private Integer clientesAfectados;
    private Integer ttrMinutos;   // Calculado al cerrar
    @ManyToOne private Equipo equipo;
}
```

#### CONTROLLER — API REST

**Endpoints del IncidenciaController:**
```
GET    /api/v1/incidencias          → Lista todas las incidencias (MySQL)
POST   /api/v1/incidencias          → Crea nueva incidencia (auto-código)
GET    /api/v1/incidencias/{id}     → Busca por ID
PUT    /api/v1/incidencias/{id}/cerrar → Cierra + calcula TTR
GET    /api/v1/incidencias/kpis     → MTTR promedio + activas
```

#### SERVICE — Lógica de Negocio

**IncidenciaService — funciones clave:**
- `generarCodigo()` → genera automáticamente `INC-20260512-001`
- `calcularTTR()` → calcula el tiempo de resolución al cerrar
- `obtenerKPIs()` → calcula MTTR promedio e incidencias activas en tiempo real
